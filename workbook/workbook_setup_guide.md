# SwiftRoute Billing Assurance Workbench
## First-time setup and refresh guide

**Workbook:** `SwiftRoute_Billing_Assurance_Workbench_v1_1.xlsx`  
**Version:** 1.1  
**Purpose:** Configure the four downstream Gold extracts in Excel Power Query, then use the two Finance review worksheets.

---

## 1. What is in the workbook

The workbook has two main Finance worksheets:

- **Billing Review**: filters the customer-period review queue, displays the selected customer-period summary, shows its supporting billing lines, and separately exposes lines that do not have a valid canonical customer mapping.
- **Receivables & Collections**: filters invoice-level AR records and displays payment linkage, recorded balances, and aging values supplied by Gold.

The sheets beginning with an underscore are technical import/control sheets. They support the two main worksheets and should not be deleted:

| Support sheet | Excel table | Load this extract |
|---|---|---|
| `_Data_Summary` | `tblBillingSummary` | Customer-period billing summary from `01_billing_review_summary.sql` |
| `_Data_Detail` | `tblBillingDetail` | Billing-line detail from `02_billing_detail.sql` |
| `_Data_AR` | `tblReceivablesRaw` | Invoice-level receivables from `03_receivables.sql` |
| `_Data_Customers` | `tblCustomerLookup` | Canonical customer lookup from `04_customer_lookup.sql` |
| `_Control` | n/a | Dynamic dropdown lists and refresh controls |

The workbook contains empty table structures only. The Billing Review summary import table has all 42 columns returned by the final SQL extract. It does **not** contain your local CSV data or preconfigured Power Query file connections. The first-time setup below connects the exported files that already exist in your project `data/exports` folder.

## 2. First-time Power Query setup

Use Excel desktop (Microsoft 365 or Excel 2021 or later is recommended because the review views use `FILTER`, `SORT` and `UNIQUE`). Keep the four CSV exports together in the same export folder if that is how you have organised the project.

For each extract, use **Data → Get Data → From File → From Text/CSV** and select the corresponding file. In the preview, confirm that the first row is recognised as the column header row. Select **Transform Data** only when you need to confirm headers or data types. Then select **Close & Load To…** and load it as a table to the specified worksheet and starting cell.

| Query name to use | Source SQL extract | Worksheet destination | Starting cell | Required Excel table name |
|---|---|---|---|---|
| `qBillingSummary` | `01_billing_review_summary.sql` | `_Data_Summary` | `A1` | `tblBillingSummary` |
| `qBillingDetail` | `02_billing_detail.sql` | `_Data_Detail` | `A1` | `tblBillingDetail` |
| `qReceivables` | `03_receivables.sql` | `_Data_AR` | `A1` | `tblReceivablesRaw` |
| `qCustomerLookup` | `04_customer_lookup.sql` | `_Data_Customers` | `A1` | `tblCustomerLookup` |

### Important table-name step

The template includes blank placeholder tables so the expected output schemas are visible. If Excel allows the query to load over the placeholder table, keep the table name shown above. If Excel reports that the destination overlaps an existing table, delete/convert **only the empty placeholder table** on that support sheet, then load the query at `A1`. After loading, select the new table and use **Table Design → Table Name** to assign the exact required name from the table above. The formulas on the two Finance worksheets depend on those names.

Do not rename source columns, remove columns, reorder the extract or manually edit imported source values. The query output column names need to remain exactly as generated by the SQL files.

### Data-type checks in Power Query

Preserve identifiers as text, especially `client_id`, `invoice_id`, `billing_line_key`, and other source keys. Dates should be date/date-time values where appropriate, and amounts/quantities should be numeric. Do not replace null expected amounts with zero. Do not create additional pricing calculations or derive new billing periods in Power Query. Use Excel Microsoft 365 or Excel 2021 or later because the review views use `FILTER`, `SORT` and `UNIQUE` dynamic-array functions.

## 3. How to use Billing Review

The filter controls are at the top of the worksheet:

- **Period filter** narrows the review queue to a Gold billing period.
- **Status filter** narrows the queue to a workbench review status.
- **Customer ID filter** narrows the queue to a canonical customer.
- **Selected customer-period key** chooses the row whose summary and billing-line detail should be displayed.

The queue is one row per customer-period. It is populated from `tblBillingSummary`. The selected summary panel uses the `customer_period_key` to retrieve the expected amount, actual invoiced amount, distinct invoice count, assessable variance, and review explanation.

To investigate a customer-period, choose its key in the selector at the top right of the filter row. The selected billing-line detail then shows service, billing unit, quantity basis, Gold invoice-ready amount, source statuses, review explanation, contract/rate references and activity dates.

The unassigned/unmapped section is separate from the normal customer review queue. It is not a 95th customer. Your validation returned 486 billing lines with `client_id = 'N/A'` and no source customer name; once the detail extract is loaded, the unassigned count should reflect those rows (subject to the same extract snapshot). These records remain available for investigation and must not be forced into a normal customer-period comparison.

A blank expected amount or blank assessable variance is intentional when the Gold source does not provide a complete, comparable amount. Do not treat blank as zero.

## 4. How to use Receivables & Collections

The invoice review queue is one row per `invoice_id`. Use the filters above it to narrow the list by billing period, aging bucket, receivable review status, customer ID and currency. The displayed invoice queue is a formula-driven spill range, not an Excel Table. Do not convert that visible range into a table. The imported AR table is `tblReceivablesRaw` on `_Data_AR`.

The KPI strip reports invoice amount, outstanding balance and 90+ days past-due balance only after a single currency is selected. It deliberately does not total financial amounts across all currencies. The invoice count and open invoice count describe the loaded AR extract.

`days_past_due` and `aging_bucket` are read from Gold. Excel does not recalculate aging with `TODAY()`. The workbook does not assign a Day 35/45/55/60 collection stage because the operating policy does not yet establish whether those day counts begin at the invoice date or due date.

## 5. Refresh procedure

For each new billing/AR snapshot:

1. Run all four downstream SQL extracts against the existing Gold models.
2. Export all four results to the controlled export folder.
3. Run the agreed SQL validation queries. Do not publish a partial batch as a successful refresh.
4. Open the workbook and select **Data → Refresh All**.
5. Confirm that all four Power Query queries refreshed without errors.
6. Check the key controls below.
7. Only after all required extracts pass, update `_Control`:
   - `B3`: last successful extract timestamp;
   - `B4`: extract batch ID, if you are recording one;
   - `B5`: `PASSED` (or the actual validation result).
8. Confirm that the Last Refreshed value on both main worksheets advances.

The timestamp is a manual control in this first release. Do not update it when only some extracts have refreshed or when validations have failed. The workbook does not yet read an automated batch manifest.

## 6. Key checks after the first load

Use these as snapshot controls, not permanent hard-coded expectations for every future refresh:

| Control | Known baseline / expected behaviour |
|---|---|
| Canonical customer lookup | 94 distinct valid customer IDs in the profile you just ran |
| Billing detail key | `billing_line_key` populated and unique |
| Unassigned billing detail | 486 rows with `client_id = 'N/A'` in your latest validation; show them separately |
| AR invoice key | `invoice_id` populated and unique |
| AR invoice count | 564 invoices in the previously validated snapshot |
| AR invoice amount | $5,714,696.41 in the previously validated snapshot; compare within a single currency |
| AR recorded outstanding balance | $1,344,188.70 in the previously validated snapshot; compare within a single currency |
| Reconciliation to AR | Reconciliation actual totals should agree with AR invoice totals at customer-period grain within the validated tolerance |
| Expected amount | Keep nulls as blank; do not replace with zero |
| Currency | Do not combine values across multiple currencies |

The exact baseline values may change with a later Gold refresh. A different count or amount is a reason to investigate the snapshot and validation output, not automatically a failure.

## 7. What the workbook does not do

The workbook is a review workpaper. It does not create or post QuickBooks invoices, change any Gold model, infer an unconfirmed customer arrangement, invent a rate or charge, allocate failed-delivery costs, or make a service suspension decision. It does not replace the SQL validation process.

The first release also does not include a persistent reviewer-notes log. Do not type review notes into a Power Query output table because a refresh can replace those cells. A separate review log can be added later if Finance needs reviewer decisions and evidence references to persist across refreshes.
